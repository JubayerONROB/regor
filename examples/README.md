# Examples

## demo_synthetic: full lifecycle on SYNTHETIC data

```bash
python examples/demo_synthetic/run_demo.py            # work dir: examples/demo_synthetic/_work (gitignored)
```

**Everything in this example is synthetic and illustrative.** The signal, the noise model
and all results are generated by `template/scripts/generate_data.py` (fixed seed). No
output is a scientific finding.

Study (toy): does a window-5 median filter give lower RMSE than a window-5 moving
average on generated impulsive noise (RQ1), and does shrinking the median window to 3
change RMSE (RQ2)?

What the demo exercises, in order:

1. project init over a template; its own git snapshot so runs are pinned
2. synthetic data generation; dataset registration and validation (time continuity, ranges, metadata)
3. experiment spec validation and a dry run
4. 3 experiments × 5 seeds run locally (baseline, proposed, ablation), validated automatically
5. seed-paired comparisons with assumption checks, Holm correction and figures with provenance
6. 7 claims registered and verified by recomputation
7. 21-section experiment reports, follow-up proposals
8. the approval gate: a Kaggle run is blocked without approval; after a (demo) approval, a
   **mock** Kaggle round trip whose run validates as INVALID by design
9. manuscript init, draft, build and audit. The audit honestly FAILs, because placeholders
   for title, introduction, discussion and declarations remain for a human to write.
10. journal profile skeleton and checklist (unknown limits stay unknown), progress report

Template layout:

```
template/
  project.yaml                      RQs, hypotheses, statistics, stopping rules
  scripts/generate_data.py          synthetic data generator
  data/demo_signals.dataset.yaml    manifest entry
  experiments/configs/EXP-*.yaml    baseline, proposed, ablation
  experiments/scripts/denoise.py    the experiment (uses regor.runtime)
```
